# 오름오름에서 가져갈 것 — 새 게임용 정리 (2026-11-15)

새 프로젝트(스팀 용병 게임)의 지침이나 지식 문서로 넣어 쓰는 문서. 오름오름의 그림체, 모델 만드는 방법, 작업 방식만 담았다. 오름오름의 게임 규칙(쓰레기·귤·오름)은 담지 않았다.

## 1. 그림체 규칙

- 한 줄 요약: 낮은 폴리곤 + 툰 명암 + 따뜻한 햇빛과 푸른 그늘 + 후처리 없음
- 빛: 따뜻한 방향광(해) 하나 + 푸른 보랏빛 반구광(그늘). 블룸·색 보정 같은 후처리는 쓰지 않는다. 색 공간 변환 없이 적은 색이 그대로 화면에 나오게 한다
- 재질: 전부 툰 재질
  - 땅·풀은 부드러운 경계: 밝기 단계 120·150·215·255 를 선형으로 이은 램프
  - 나무·바위·캐릭터·동물은 또렷한 3단: 105·105·205·255 를 끊어 쓴 램프
- 시간대는 값 묶음으로 관리한다: 해 높이·해 색·세기, 반구광, 하늘 위·수평선 색, 구름 2색이 한 묶음. 오름오름은 낮(해 56°), 늦은 오후(23°, 기본), 노을(6.5°), 밤을 쓴다
- 땅 색 예: 풀 #62a64a·#86c257·#b9d264, 마른 풀 #d8b562, 붉은 흙 #a3553d, 길 #dcbb8c. 붓질 텍스처(512px, 큰 붓·중간·잔붓 3채널)로 섞어 손그림 느낌을 낸다
- 나무: 구 4~5개를 뭉친 수관(법선을 수관 중심 기준으로 둥글게, 아래쪽은 어둡게) + 층층 침엽수. 인스턴싱, 바람에 흔들림
- 풀: 플레이어 주변 칸에만 인스턴싱(데스크톱 약 5만, 모바일 약 1.7만 포기), 바람·밟으면 눕기, 땅 색을 그대로 받음
- 그림자: 방향광 그림자 1장이 플레이어를 따라다님(텍셀 단위로 스냅해 떨림 방지)
- 가림 처리: 나무·바위가 카메라와 캐릭터 사이에 오면 4×4 디더로 비치게 한다
- 캐릭터·동물: 아늑한 생활 게임풍 토이 스타일. 머리가 키의 약 40%, 매끈한 점토 질감, 얼굴에 인쇄한 듯 평평한 큰 세로 타원 눈, 코·입 없음, 볼터치 없음
- UI: 검은 유리(rgba(20,20,24,.5) + 흐림 12, 1px 흰 테두리 16%), 포인트 색 하나(귤색 #ff8a1f), 글자는 최소로 하고 아이콘 중심
- 레퍼런스: 웹 게임 Summer Afternoon(vlucendo)

## 2. 모델 만드는 방법 (Tripo)

1. Tripo 스튜디오(studio.tripo3d.ai)의 이미지 생성(무료, Nano Banana)으로 시안을 4장씩 뽑는다
2. 사용자가 번호로 고른다. 고칠 점은 같은 화면의 이미지 편집으로 고친다(예: 볼터치 제거, T포즈로 바꾸기)
3. 고른 그림을 '3D 생성'으로 넘긴다(55크레딧, HD 모델). 결과는 약 190만 삼각형·60MB
4. GLB 로 내보내 받는다. 원본은 저장소의 별도 `assets` 브랜치에 둔다(본 브랜치에는 넣지 않음)
5. Blender(`pip install bpy`)로 줄이고 텍스처를 굽는다. 오름오름 기준: 플레이어 캐릭터 9,000 삼각형, 멧돼지 1,500 삼각형·텍스처 512, 돌담 조각 가까이용 400·멀리용 60 삼각형
6. 뼈대는 직접 붙인다. 캐릭터는 뼈 7개(엉덩이·가슴·머리·양팔·양다리) 가중치를 정점 위치로 계산했다

시안 프롬프트 틀(영어로 쓴다)
- 캐릭터·동물: `Original character, one animal only: <대상>, full body, three-quarter front view, standing, plain light gray background. Smooth rounded toy-like 3D render in a cozy life-sim game style, matte clay material. <몸 비율·특징>. Large flat vertical oval black eyes that look printed on the face. Soft studio lighting, no text.`
- 소품·구조물: `One <대상>, single isolated game asset, side three-quarter view. Stylized low-poly toy-like 3D render, chunky faceted shapes, matte <색>, no ground, plain light gray background, soft studio lighting, no text.`
- 이어 붙일 조각(담·울타리)은 `both ends cut flat so segments can be placed end to end` 를 넣는다

주의
- Tripo CLI·API 는 스튜디오와 크레딧이 따로라 쓰지 않는다. 사용자 맥의 크롬에 로그인된 스튜디오를 Claude 가 브라우저로 조작한다
- 클라우드에서 도는 자동 세션은 Tripo 를 못 쓴다. 모델은 기획 세션에서 만들어 저장소에 올리고, 적용만 자동 세션에 넘긴다
- 60MB 원본은 작업 공간으로 올리다 실패한 적이 있다. 맥에서 gltf-transform 으로 먼저 줄여 올린다

## 3. 작업 방식

- 기획 세션 하나에서 사용자와 기획하고, 정해진 것은 GitHub 이슈로 만든다
- 이슈는 사안별로 잡고, 본문만 읽고 시작할 수 있게 필요한 결정·수치·관련 파일을 다 적는다
- 이슈마다 새 세션이 자동으로 떠서 수행한다. 예약 작업 둘(Opus 용, Sonnet 용)이 `notes/queue.md` 의 순서대로 이슈를 하나씩 맡고, 끝나면 다음 예약 작업을 실행한다. 단순한 이슈는 Sonnet, 설계나 그림체가 중요한 이슈는 Opus
- 자동 세션의 규칙은 저장소의 `notes/auto.md` 한 파일에 둔다: 이슈 읽기 → work/ 브랜치 → 구현 → 빌드·오류 확인 → dev 에 합치기 → 이슈 코멘트·닫기. 확인이 통과하지 못하면 합치지 않고 멈춘다
- 브랜치: `work/<이슈 번호>-<이름>` → `dev`(개발 서버 자동 게시) → `release`(실서버, 사용자가 "배포해줘"라고 할 때만)
- 수치는 한 파일(`balance`)에 모은다. 새 3D 오브젝트는 임시 모양으로 먼저 넣고 사용자가 보고 고친다
- 사용자는 개발 서버에서 직접 해 보고 기획 세션에 피드백을 준다. 기획 세션이 이슈로 정리해 순서에 넣는다
- 답변은 한글로 짧게, 항목마다 번호를 붙인다. 사용자가 번호로 답하면 그 항목에 대한 답으로 읽는다
- 기획 세션이 무거워지면 새 세션으로 갈아탄다. 결정은 그때그때 기획서와 이슈에 남긴다

## 4. 다른 엔진으로 옮길 때

- 툰 명암은 밝기 램프 텍스처(위의 4단계 값)를 읽는 셰이더로 그대로 옮길 수 있다
- 나무·풀·돌담·병사처럼 많은 것은 인스턴싱으로 그린다(Godot 는 MultiMeshInstance3D)
- 후처리를 켜지 않는다. 톤 매핑도 끄거나 선형으로 두어 색이 바뀌지 않게 한다
- 모델은 GLB 그대로 가져간다

## 5. 참고할 파일 (저장소 spaceHWI/oreumoreum, dev 브랜치)

- 그림체 구현: `src/namsongi.js`(지형·풀·나무·하늘·빛), `src/toon.js`(명암 램프)
- 캐릭터: `src/runner.js`, `src/runnermodel.js`, `model/bake.py`(줄이기·굽기), `model/extract.js`
