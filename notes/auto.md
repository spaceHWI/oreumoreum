# 자동 세션 규칙

예약 작업으로 뜬 세션이 이슈 하나를 끝까지 수행할 때 따른다. 사람이 지켜보지 않으므로 질문하지 않는다.

## 시작
1. 맡을 이슈는 `notes/queue.md` 에서 위에서부터 처음으로 열려 있는 이슈 하나다. `gh api repos/spaceHWI/oreumoreum/issues/<번호>` 로 이슈 본문과 코멘트를 읽는다. 기획 전체는 `notes/spec.md`, 코드 구조는 `notes/prototype-v1.md`
2. 최신 `dev` 에서 `work/<번호>-<짧은 이름>` 브랜치를 만든다
   - **여러 실행이 나란히 돈다.** 맡기 전에 그 이슈를 다른 실행이 하고 있는지 본다: origin 에 `work/<번호>-*` 브랜치가 있거나(`git ls-remote origin 'refs/heads/work/<번호>-*'`), 이슈에 '작업 시작' 코멘트가 3시간 안에 달려 있으면 하는 중이다. 그러면 건너뛰고 그다음 열린 이슈를 본다(실행 글이 줄을 정해 줬으면 그 줄 안에서)
   - 맡기로 했으면 **바로** 이슈에 '작업 시작 (<모델>)' 한 줄 코멘트를 달고, 빈 커밋이라도 해서 `work/` 브랜치를 먼저 origin 에 올린다(다른 실행이 같은 이슈를 잡지 않게)
   - `notes/queue.md` 의 '줄' 표(나란히 도는 묶음)를 보고, 실행 글에 줄 이름이 있으면 그 줄의 이슈만 한다
3. 앞 이슈에서 만든 코드를 먼저 읽고 그 위에 얹는다

## 만들 때
- 이슈에 적힌 것만 한다. 무관한 코드는 고치지 않는다
- 게임 코드는 `src/game/` 기능별 파일에 있다 (`src/main.js` 는 순서대로 읽기만). 파일 하나는 40KB 를 넘기지 않는다. 파일 사이 값 주고받기 규칙은 `notes/prototype-v1.md` 코드 구조
- 남송이오름 기준. 새 3D 오브젝트는 지금 그림체(`toon.js`, `namsongi.js` 재질)에 맞춘 로우폴리 임시 모양으로 만든다
- UI 는 `src/page.html` 의 현무암 UI 토큰을 쓴다. 글자는 최소로, 아이콘 중심. 폰(폭 600 이하)과 데스크톱 둘 다
- 저사양(LOW)에서도 프레임이 떨어지지 않게 한다
- 저장은 `save` + `persist()`. 예전 저장 데이터로 시작해도 오류가 없어야 한다
- 멀티는 붙이지 않는다. 다만 쓰레기 상태를 읽고 쓰는 부분은 한곳에 모아 나중에 서버로 바꾸기 쉽게 한다
- 수치는 한 파일(예: `src/balance.js`)에 모은다

## 확인
- `npm ci` 후 `node build.mjs` 통과 (빌드가 `tools/lint.js` 로 줄 중간 `//` 주석·300자 넘는 줄의 `//` 를 막는다. 걸리면 `/* */` 로 쓰거나 줄을 나눈다)
- `node tools/smoke.js` 통과 (새 사용자 튜토리얼 첫 단계·게임 루프 셈·걷기·줍기·던지기·가게·가방, 폰·PC). 게임 루프(`src/game/update.js`)에 새 시스템을 붙이면 `state.ticks` 와 `smoke.js` 의 `LOOP` 에 한 줄 더한다. 루프는 문장마다 한 줄
- `tools/err.js` 를 남송이 기준으로 돌려 페이지 오류가 없는지 확인 (필요하면 스크립트의 주소 해시를 고쳐 쓴다). 스크린샷은 꼭 필요할 때만, 작게
- 새 기능은 `window.__oreum` 으로 값을 넣어 보며 동작을 확인한다
- 귤이 늘어나는 새 기능은 '서버가 그 몫을 아는가' 를 확인한다 (#188): 기록이 저장에 남는 큰 보상이면 `server/src/earn.js` 에 인정 길을 더하고, 아니면 한 번에 `NET.earnBurst` 를 넘지 않는지 본다. `tools/sec.js` 에 그 몫을 받아 주는 줄·두 번 받기 거절 줄을 더한다
- **검사가 실패하면 '이 작업 전 dev 에서도 실패' 라고 넘기지 않는다** (#193). 그 자리에서 고치거나(낡은 검사면 검사를) 새 이슈를 올리고 그 번호를 코멘트에 적는다
- 수치(`src/balance.js`, `NET` 한도 포함)를 바꾸는 이슈는 `node tools/online.js`(로컬 서버 `cd server && npm run dev`)·`node tools/sec.js` 를 끝까지 돌려 통과시킨다. 실패를 '관계없음' 으로 남기지 않는다: 낡은 검사면 검사를 고치고, 진짜 구멍이면 코드를 고친다 (#144)
- 검사가 여는 `test.html`(file://)은 안티에일리어싱을 끈다(소프트웨어 GL 에서 2배 빠름, #286). 그림 비교·성능 재기처럼 실제 모양이 필요하면 주소에 `?aa=1`. 이야기·감독을 기다리는 검사는 실제 시간보다 감독 시계(`__oreum.director.api.clock`)로 기다리고, 막히면 `__oreum.director.why(kind)` 로 까닭을 본다
- `sec.js`·`rankrun.js` 는 스스로 로컬 서버를 띄운다. 앞 실행이 `timeout` 등으로 끊겨 서버가 남아 있으면 시작할 때 그것을 끄고 새로 띄운다(#259, `tools/localsrv.js`). 서버 쪽 줄이 날마다 늘어나는 수·지난 날짜로 무더기로 실패하면 남은 서버(`ps aux | grep workerd`)부터 의심한다. 긴 검사는 `timeout` 보다 넉넉한 시간으로 돌린다
- `online.js` 통째는 소프트웨어 GL 에서 10분을 넘기기도 한다 (#245). 백그라운드로 돌려(`nohup … > 로그 &`) 로그를 보거나, 나눠 돌린다: `node tools/online.js <서버> core`(동굴·레이드·귤 주기 뺀 나머지) → `… cave` → `… raid` → `node tools/give.js <서버>`. 넷이 모두 통과하면 통째 통과로 본다. 하나만 볼 땐 `deer`·`emote`·`cart` 도 있다. 레이드는 시작할 때 앞 실행이 남긴 레이드를 지우고(`raid.start(true)`, 로컬 STATS_OPEN 방만) 새로 열어서 앞 실행과 상관없다

## 오류 알림 이슈
제목이 `[오류]` 로 시작하는 이슈 (실서버 오류 알림 `GET <서버>/crashes?days=3` 에서 온 것)
- `node tools/crashmap.js <버전> <main-해시.js:줄:칸>` 으로 원래 파일·줄·함수를 찾는다 (이슈의 오류 글을 통째로 넣어도 됨)
- 원인이 분명하면 고친다 (같은 원인이 다른 곳에도 있는지 본다)
- 분명하지 않으면 안전장치(널 확인 등)를 함부로 덧대지 않는다. 무엇을 더 알아야 하는지(어떤 기기·어떤 동작 뒤·어떤 값) 코멘트하고 이슈를 열어 둔다. 이때는 다음 작업도 실행하지 않는다

## 끝
1. 커밋하고 `work/` 브랜치를 올린다: `git -c push.negotiate=true push -u origin <브랜치>`
2. 확인이 통과했으면 `dev` 에 합쳐 올린다. 다른 실행이 그새 dev 를 바꿨을 수 있으니 합치기 직전에 `git pull` 로 받고, 충돌은 양쪽 의도를 살려 고친 뒤, **충돌이 없어도 합친 뒤의 dev 에서** 빌드·`err.js`·`smoke.js` 를 한 번 더 돌린다 (나란히 도는 다른 실행의 변경과 합쳐진 상태로, #193). 실패하면 push 하지 않는다. push 가 거절되면 다시 받아 합친다 (`git checkout dev && git pull --ff-only origin dev && git merge --no-ff <브랜치> && git push origin dev`). 개발 서버에 자동 게시된다
3. 이슈 메모(바꾼 것·결정 사항)는 `notes/history.md` 끝에 몇 줄 더하고, 파일 구성이 바뀌었으면 `notes/prototype-v1.md` 의 코드 구조도 고친다 (2의 합치기 전에)
4. 이슈에 결과 코멘트(바꾼 것, dev 에서 확인하는 방법, 임시로 둔 것·남은 점)를 달고 이슈를 닫는다
5. (실행 글에 줄 이름이 있으면 그 줄에서, 다른 실행이 하는 중인 것은 빼고) `notes/queue.md` 에서 다음으로 열려 있는 이슈를 찾아, 그 이슈의 모델에 맞는 예약 작업을 `fire_trigger` 도구로 실행한다 (ToolSearch 로 `select:mcp__claude-code-remote__fire_trigger`, 예약 작업 ID 는 프롬프트에 있음). 남은 이슈가 없거나 도구가 없으면 넘어간다
- 확인이 통과하지 못하고 고칠 수 없으면: `dev` 에 합치지 않고, 이슈에 막힌 점을 코멘트로 남기고, 이슈를 닫지 않고, 다음 작업도 실행하지 않는다
- `release`·`main` 은 건드리지 않는다. PR 은 만들지 않는다
- 답변은 한글로 짧게
- 일하는 방법 자체를 바꿨거나 더 나은 방법을 찾았으면 `notes/process.md` 의 해당 절과 '바뀐 기록' 에 한 줄 적는다 (다음 게임에도 쓰는 문서)
